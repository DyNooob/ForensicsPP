# ForensicsPP 1.0.0-beta.7 — 候选功能计划

> 计划日期：2026-09-01 ｜ 评估依据：`docs/beta6/TOOL-CANDIDATE-EVAL-2026-09-01.md`
> 定位：浏览器 DFIR 工具箱，零上传、隐私优先。beta.7 在 beta.6（证据柜 / envelope / 首跑引导 / 性能矩阵 等）之后。

## 候选功能清单（6 项）

| # | 功能 | 浏览器可行性 | 数据依赖 | 隐私 | 优先级 |
|---|------|------|------|------|------|
| 1 | 身份证号归属地查询 | ✅ 最易（GB/T 2260） | 行政区划代码库（~几百 KB，公开国标） | ⚠️ PII，必须本地 | **P0（示范工具）** |
| 2 | 手机号归属地查询 | ✅（号段库） | 号段 → 省/市/运营商（~1–2 MB，公开） | ⚠️ PII，必须本地 | **P0** |
| 3 | IP 静态库查询 | ✅ | ip2region xdb（几 MB，Apache-2.0） | 本地，IP 不出机 | **P0** |
| 4 | 银行卡号归属地查询 | ✅（BIN） | 开源 BIN 有限库（授权风险） | ⚠️ PII，必须本地 | **P0（受数据授权制约）** |
| 5 | 一键校时 | ⚠️ 受限 | HTTP-time / wasm NTP-over-HTTP | 无 PII | **P1（偏差检测）** |
| 6 | 一键录屏 | ⚠️ 受限 | getDisplayMedia + MediaRecorder | 本地 webm | **P1（工作记录）** |

## 实施顺序建议

1. **第一批（P0，零风险，离线 + 本地）**：身份证号归属地 → 手机号归属地 → IP 静态库查询。
   - 三者均 100% 本地、零上传，契合产品定位，工作量小，建议作为 beta.7 首个里程碑。
2. **银行卡号归属地**：先做「开源 BIN 有限覆盖」，UI 标注数据来源与局限性；完整库待授权评估。
3. **第二批（P1，浏览器受限）**：
   - 一键校时：定义为「一键校时检查」——显示本机与标准时间的偏差，不做系统时钟写入。
   - 一键录屏：定义为「勘验过程记录」——webm 本地录制 + 计时水印，非正规证据格式。
   - 两者正式能力（真正校时 / 高质量录屏）留待 Electron / 桌面壳（beta.8+ 或独立壳）。

## 统一隐私护栏（硬性）

- 所有 PII 查询（手机 / 身份证 / 银行卡）：**禁止任何网络外发、禁止持久化输入值**；代码层禁用 fetch 上报，UI 明确告知「查询全程在本地完成」。
- 数据内置随包分发，注意体积与更新机制（号段 / IP 库需可更新）。

## 范围与排除

- 本计划不含 beta.6 已交付项（证据柜、envelope 覆盖、首跑引导、性能矩阵等）。
- 校时 / 录屏若需突破浏览器限制，单独评估桌面壳方案，不在 beta.7 纯前端 scope 内。
