- **数据来源与授权**：是否需内置离线库、库体积与再分发许可。

## 逐项评估

### 1. 一键校时
- **可行性（浏览器）**：⚠️ 受限。浏览器无权限修改操作系统时钟，无法真正"校"——只能"测"。
  可行范围 = 一键获取本机时间与标准时间的偏差（clock skew / offset）。
- **技术路径**：NTP 走 UDP，浏览器无法直接发；需经 HTTP-time 端点或内置轻量 wasm NTP-over-HTTP
  客户端取权威时间，比对 `Date.now()` 与 `performance.timeOrigin`，输出偏差与提示。
- **数据 / 合规**：无 PII；建议默认走本地 / 可信 NTP 镜像，避免外泄 examiner 行为。
- **取证价值**：中。时间轴准确性是取证核心，偏差提示有价值；但"一键把系统时间改对"在浏览器内做不到。
- **建议**：定义为"一键校时检查（显示本机与标准时间偏差）"，scope 收窄；真正校时需 Electron / 桌面壳。
- **优先级**：P1（受限功能，建议 beta.7+，桌面壳优先）。

### 2. 一键录屏
- **可行性（浏览器）**：⚠️ 受限但可用。可用 `getDisplayMedia` + `MediaRecorder` 录屏 / 录窗，存为 webm；
  每次需用户授权，无法后台自动录制，输出为 webm（非标准取证视频封装）。
- **技术路径**：捕获流 → MediaRecorder → Blob → 下载 / 存工作区；可叠加计时水印与操作注释。
- **数据 / 合规**：全程本地，无上传；webm 仅作工作记录，非正规证据格式。
- **取证价值**：中。记录勘验过程（操作留痕）有价值；格式与可控性弱于专业录屏。
- **建议**：作为"勘验过程记录"轻量工具；正式取证录屏仍建议专用软件。桌面壳可大幅提升。
- **优先级**：P1。

### 3. IP 静态库查询
- **可行性（浏览器）**：✅ 可行。内置离线 IP 地理 / ASN 库，纯前端查询。
- **技术路径**：内置 ip2region xdb 或同类离线库（几 MB，wasm / JS 查询），输入 IP →
  输出 国家 / 省 / 市 / 运营商 / ASN。
- **数据 / 授权**：ip2region（Apache-2.0，可再分发）；MaxMind GeoLite2 需许可密钥、不可随意再分发——
  选 ip2region 更稳。库需随包分发，注意体积。
- **隐私合规**：查询在本地完成，IP 不出本机；符合零上传定位。
- **取证价值**：高。IP 归属 / ASN 是网络取证高频需求。
- **优先级**：P0（高价值、低风险、契合定位）。

### 4. 手机号归属地查询
- **可行性**：✅ 可行。内置号段库，纯前端查询。
- **技术路径**：内置 手机号号段 →（省 / 市 / 运营商）映射（公开号段数据，约 1–2MB），前 7 位查归属地。
- **数据 / 授权**：号段数据来自工信部公开分配，可内置；注意定期更新。
- **隐私合规**：⚠️ 输入为手机号（PII）。必须 100% 本地、不联网、不持久化输入。ForensicsPP 的零上传定位
  正好满足，但需显式保证（代码层禁用任何外发）。
- **取证价值**：高。
- **优先级**：P0。

### 5. 身份证号归属地查询
- **可行性**：✅ 可行（最易）。内置 GB/T 2260 行政区划代码。
- **技术路径**：前 6 位（地址码）→ 省 / 市 / 区县；可顺带校验 18 位校验位、解析出生日期 / 性别。
- **数据 / 授权**：GB/T 2260 为公开国标，体积小（几百 KB）。
- **隐私合规**：⚠️ 身份证号高度敏感 PII。必须本地、不联网、不存储。仅显示 籍贯 / 发证地。
- **取证价值**：高，且实现最简单 → 建议作为示范工具优先落地。
- **优先级**：P0（最优先，性价比最高）。

### 6. 银行卡号归属地查询
- **可行性**：✅ 技术可行（BIN 查询）；⚠️ 数据授权风险。
- **技术路径**：前 6–8 位 BIN → 发卡行 / 卡种 / 卡组织。
- **数据 / 授权**：⚠️ 完整 BIN 库多为商业 / 银联授权数据，开源离线库覆盖与准确性参差，再分发存在合规不确定性。
  需评估数据源合法性或仅做有限开源 BIN。
- **隐私合规**：⚠️ 卡号敏感 PII，必须本地、不联网、不存储。
- **取证价值**：中高（资金链路溯源常用）。
- **优先级**：P0（价值高）但受数据授权制约，建议先做"开源 BIN 有限覆盖"并标注数据来源与局限性。

## 结论与建议下一步
1. **先落地 3 个零风险 P0**：身份证号归属地（示范）、手机号归属地、IP 静态库查询——
   均离线、本地、零上传，契合定位，工作量小。
2. **银行卡归属地**先做开源 BIN 有限版，标注数据局限。
3. **校时 / 录屏**定义为"浏览器受限版"（校时 = 偏差检测；录屏 = webm 工作记录），
   正式能力留待 Electron / 桌面壳。
4. **统一隐私护栏**：所有 PII 查询工具强制"不联网、不持久化输入"，并在 UI 明确告知用户。
