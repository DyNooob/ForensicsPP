# 检查结果与异常分级

中文界面将程序产生的检查标题、已知错误、限制说明和修复说明以中文呈现。格式名称、协议字段、十六进制偏移、哈希值及原始证据内容保留原样。对于未收录的解析器错误，界面提供中文上下文，并在“原始错误信息”中保留具体技术信息。

| 级别 | 颜色与标签 | 含义 |
| --- | --- | --- |
| 明确异常 | 红色 · 异常 | 校验失败、无效结构、解码或操作失败等实际检查结果 |
| 需要复核 | 橙色 · 需关注 | 私有块、附加内容、宏、外部引用、捕获缺口等待核实线索 |
| 检查通过 | 绿色 · 检查通过 | 某项明确执行的校验通过，不代表整个文件安全或真实 |
| 范围说明 | 蓝色 · 说明 | 已提取的常规元数据、分析边界或统计信息 |
| 尚未执行 | 灰色 · 未检查 | 未生成的像素预览、未提供密钥的签名校验等，不作为通过处理 |

分级使用文字标签与颜色共同表达。元数据较多、存在透明像素或普通文本块本身不会被直接列为异常。原始文件、元数据值及分析器导出数据不因界面翻译而改写。

## 图片工作台

概览优先显示检查结论和异常证据，再提供四个固定入口：结构与校验、宽高与容器修复、附加与隐藏内容、像素与位平面。可读取的 EXIF 重点字段与完整元数据继续显示。结构页默认显示已产生的检查记录，不必先切换到格式子页才看到异常。

图片无法解码时，文件头中的宽高标为“声明尺寸（未验证）”。像素检查需要可解码的图片；容器、数据块与可读取的元数据仍然可以分析。

## PNG 宽高恢复

打开图片后进入“修复”，点击“恢复宽高 / 检查修复”。处理在本地 Worker 内进行，依据 [W3C PNG 规范](https://www.w3.org/TR/png/) 的 IHDR、过滤扫描行和 Adam7 布局进行验证。

1. 合并 IDAT 并流式解压 zlib 数据，验证压缩流完整性。
2. 在宽高 `1–65535`、总像素不超过 `50,000,000` 的范围内搜索；通过 CRC 线性反解推导高度，避免对宽高执行完整二维循环。
3. 核对候选的位深、颜色类型、扫描行总长度和过滤字节；支持 PNG 合法位深与 Adam7 七遍交错。
4. 原 IHDR CRC 与完整扫描行同时匹配时报告恢复尺寸。若原 CRC 也被改写，则根据扫描行提供待核实候选，不宣称唯一恢复。
5. 浏览器再次解码候选预览。可导出副本，也可选择“分析此副本”继续通道、位平面等分析。

宽高修复只修改副本的 IHDR 宽高和该块 CRC，保留压缩像素、辅助块及尾部数据。原图和修复副本可对照。单独“重建 PNG 关键数据块”会移除部分块和尾部内容，并明确标注其操作范围；它本身不恢复宽高。

解压输出上限为 `64 MiB`，扫描行检查预算为 `8,000,000` 次。最多保留 8 个尺寸候选，候选副本总大小另受 `64 MiB` 预算限制。超限或未匹配会给出原因，不能据此判断不存在隐写。其他 IHDR 字段损坏、IDAT 损坏、截断或超出范围的图片可能无法恢复。

## 简繁转换

从左侧“转换”分类直接打开“简繁转换”，不需要进入编码解码。内置 OpenCC 词库支持双向转换、台湾与香港字形和地区词汇。`Ctrl / ⌘ + Enter` 转简体，加 `Shift` 转繁体。输入与文件转换限制为 `2 MiB`；文件按 UTF-8 读取。姓名和一对多字形仍需结合原文复核。

## 验证入口

- `npm test`：解析、恢复、分级、翻译及证据保真回归。
- `npm run smoke:image-recovery`：生产构建下使用真实 Chrome，检查尺寸篡改、超大声明尺寸、恢复字节与像素一致性、移动布局和独立简繁入口。
- `npm run smoke:offline`：首次启动、全工具初始化及关键功能的断网检查。
