# Forensics++ v1.0.0-beta.3

Release date: 2026-08-16

`1.0.0-beta.3` turns the existing embedded-file carver into a dedicated **Firmware Analyzer** and continues the architectural migration started in beta.2. The main goal is not another isolated tool: format detection, recursive expansion, analyzer routing, structured results and case serialization now share explicit core services.

## Firmware Analyzer

The new workspace provides a browser-native, Binwalk-like triage path without claiming Binwalk CLI compatibility:

- `EvidenceReader`/Worker based chunk scanning instead of whole-file loading.
- Signature detection across chunk boundaries.
- Exact/structural/heuristic/unknown extent confidence.
- Incremental source SHA-256 and bounded entropy map.
- Architecture hints for common ELF/PE/U-Boot objects.
- Firmware metadata for U-Boot, SquashFS, DTB, Android boot/sparse, UBI/JFFS2 and related structures.
- Recursive ZIP/APK/JAR, gzip, zlib, TAR and CPIO expansion under explicit safety limits.
- Interesting-path triage, selective extraction, Hex context and direct analyzer handoff.
- `forensicspp.firmware-manifest/v1` JSON export with offsets, hashes, extent confidence, ancestry and analyzer target.

Complex filesystem/compression formats that are not natively unpacked are still identified/carved; the UI does not imply successful mounting or extraction when only a signature/extent is available.

## Architecture changes

- Carver formats are exposed as a reusable Registry.
- Archive recursion moved into a shared container extractor.
- Analyzer selection moved to `src/core/analyzerRouting.ts`.
- Tool Handoff now uses bounded per-target FIFO queues instead of a single overwriteable pending object.
- Result Store adds bounded history, subscriptions and safe snapshots.
- `.fppcase` schema 1.1 adds `analysis.json` while remaining compatible with 1.0 packages.
- Disk Image consumes carved filesystem handoffs, closing the Firmware → Disk workflow.
- Tool definitions now expose accepts/capabilities metadata for search and future capability-aware dispatch.
- Object-level SHA-256 uses a bounded total-read budget; source SHA-256 remains complete. Boundary fallback uses precomputed next-object offsets to avoid repeated array scans.

## Compatibility and limits

- Existing beta.2 workspaces and analyzers remain available.
- `.fppcase` 1.0 remains importable; new exports use 1.1.
- Large firmware remains top-level streaming analysis; automatic recursive expansion is intentionally bounded.
- SquashFS/UBIFS/JFFS2/XZ/LZMA/Bzip2 and similar formats can be identified/carved, but not every format has a native browser extractor yet.
- Firmware Analyzer is a DFIR triage workbench, not a promise of byte-for-byte Binwalk CLI output compatibility.

## Verification performed in the development environment

- Copyright-header validation across source/test files.
- TS/TSX syntax transpile validation across the repository.
- Strict TypeScript checks for the new core Firmware/Carver/Container/Result/Handoff modules using isolated dependency declarations.
- Synthetic runtime validation for cross-chunk magic detection, U-Boot structural extent/architecture metadata, entropy generation and Firmware Manifest export.
- Recursive TAR → SQLite extraction runtime validation.

A complete release build still requires a normal npm dependency environment:

```bash
npm ci
npm run verify
```
