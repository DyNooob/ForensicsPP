# Forensics++ v1.0.0-beta.2

## 中文

`1.0.0-beta.2` 把 Forensics++ 从“工具数量扩展”转向浏览器端 DFIR 分析底座和深度能力。核心变化是 EvidenceReader、结构化分析结果、Tool Registry，以及围绕 APK、Firmware、SQLite、PCAP、Disk、NTFS 和案件包的取证能力深化。

### APK 签名验证与重签

- v1/JAR：Manifest entry digest、`.SF` digest、常见 RSA/ECDSA CMS signer signature。
- v2/v3/v3.1：Signer signature、证书/公钥一致性、APK 1 MiB chunk content digest、v3 SDK 范围。
- v4：可选择独立 `.idsig`，校验 signed data、fs-verity Merkle root/tree，并与 APK 内 v2/v3 signer/digest 对照。
- “签名修复”采用合法重新签名：导入 PKCS#8 + X.509，或生成本地临时修复身份，构建新的 v2 Signing Block 并自验证。

没有原开发者私钥时，Forensics++ 不会声称可以恢复原签名身份；重新签名后的 APK 是新的签名身份，通常不能作为原证书应用的无缝更新包。

### 取证能力

- SQLite Deleted Record Recovery 增加 Overflow Page 重组与历史 WAL 版本。
- Firmware/File Carver 增加安全递归 ZIP/gzip 展开和 Analyzer Handoff。
- PCAP 增加 TLS SNI/ALPN/version/cipher/JA3/JA3S/certificate fingerprint。
- PE/ELF 增加 imports/exports/PDB/overlay/security、dynamic/NEEDED/symbol/build-id 等静态 triage。
- Disk Image Explorer 增加 MBR/GPT 与 NTFS/FAT/exFAT/EXT/ISO 元数据，FAT 根目录只读浏览。
- Windows Artifact 增加 `$MFT` 和 `$UsnJrnl:$J`。
- 新增流式 Bulk Artifact Scanner 与 Memory/Minidump Triage。
- 新增 `.fppcase` 版本化参考型案件包，内部文件带 SHA-256 完整性清单。

### 架构

- `EvidenceReader` 为大检材提供 `File.slice()` 随机读取接口。
- `AnalysisEnvelope<T>` 和 Result Store 为 UI、Reporter、Timeline、Export 提供结构化结果通道。
- Tool lazy-loader/service injection 收敛到 Tool Runtime Registry。
- Android/Archive 共用 ZIP Central Directory 膨胀预检。

### 验证说明

本开发环境完成了版权头检查、全仓 TS/TSX 语法转译、核心解析器严格类型检查，以及多个真实/合成独立样本的正负向运行验证，包括 v1 RSA/ECDSA、v2 重签与篡改、v4 `.idsig` 篡改、SQLite overflow、Disk/FAT、MFT/USN、Memory、Bulk、递归 Carver 和 `.fppcase` 完整性。

由于当前执行环境没有完整 npm 依赖缓存，本包不声称已经在这里完成完整 `npm run verify`。发布前必须在正常依赖环境运行：

```bash
npm ci
npm run verify
```

## English

`1.0.0-beta.2` shifts Forensics++ from tool-count growth toward a browser-native DFIR foundation and deeper parsers.

Highlights include random-access `EvidenceReader`, structured `AnalysisEnvelope` results, a runtime tool registry, recursive firmware/file carving, SQLite overflow/deleted-record recovery, TLS metadata, deeper PE/ELF triage, disk/NTFS artifact triage, versioned `.fppcase`, and Android signature verification across v1/v2/v3/v3.1 with optional v4 `.idsig` verification.

APK “repair” is explicit re-signing. A user-supplied PKCS#8/X.509 identity or a locally generated temporary repair identity can produce a new v2-signed APK. An unknown original developer private key cannot be reconstructed, so the tool does not present re-signing as restoration of the original application identity.

Before publishing this beta, run `npm ci && npm run verify` in a complete dependency environment.
