# Forensics++ v1.0.0-beta.4

Release date: 2026-08-16

`1.0.0-beta.4` is a consolidation and performance release. It reduces duplicated top-level tools by moving capabilities that share the same evidence into reusable workbenches, and it removes the largest sources of repeated I/O in Firmware Analyzer.

## Workbench consolidation

### Image Workbench

PNG structure analysis and QR decoding now live inside the existing Image Workbench. One opened image can be inspected for metadata, PNG chunks/CRC, hidden/trailing data, QR content and repair operations without being uploaded/opened again in separate tools.

Legacy `#png` and `#qr` routes are retained as hidden compatibility aliases and open the matching Image Workbench page.

### Binary Workbench

File identification, strings/IOC extraction, entropy and YARA are consolidated into Binary Workbench alongside Hex, executable structure and embedded-object analysis.

Strings, entropy and YARA remain on-demand worker operations. Consolidation therefore shares the source file and workspace state without eagerly performing every expensive analysis when a file is opened.

Legacy `#fileid`, `#strings`, `#entropy` and `#yara` routes are retained as hidden compatibility aliases.

See `docs/WORKBENCH_CONSOLIDATION.md` for the merge criteria and capabilities intentionally kept as separate analyzers.

## Firmware performance

Firmware Analyzer no longer performs an independent multi-megabyte generic carver scan for every signature candidate. Candidate boundary resolution now calls the matched format definition directly using bounded header probes.

Other changes include:

- source scan chunk size increased to 8 MiB;
- signature lookup grouped by first byte and uses typed-array search rather than a JavaScript map lookup for every source byte;
- entropy histogram and zero-ratio calculation share one byte pass;
- PE/ELF receive a larger bounded header probe while most formats use a 256 KiB probe;
- recursive analysis no longer rereads and rescans the whole source for smaller firmware; only recognized root containers are expanded;
- recursive container reads are explicitly budgeted;
- object SHA-256 rereads use a smaller total budget;
- parent assignment avoids repeated filter/sort passes;
- Firmware results expose scan/resolve/recursive/total timing metrics.
- once the configured object cap is reached, later chunks skip signature matching while source SHA-256 and entropy accounting continue.

A regression test constrains source read amplification for a 16 MiB synthetic firmware containing 12 U-Boot signatures. With object pre-hashing disabled, beta.4 must remain below 1.5x source bytes read.

In the development environment, the same synthetic case changed from approximately 7.56x source reads and 1.56 seconds on beta.3 to 1.19x and 0.37 seconds on beta.4. This is a focused synthetic benchmark, not a guarantee of the same speedup for every firmware image.

## Architecture changes

- Tool definitions can be hidden compatibility aliases with a canonical `mergedInto` workbench.
- Sidebar, Home/search, recent tools, favorites and hash routing operate on canonical visible workbenches.
- Runtime registry no longer lazy-loads separate PNG/QR/File ID/Strings/Entropy/YARA tool chains.
- Image and Binary workbenches preserve legacy route intent by opening the appropriate page.
- Firmware timing and read-amplification behavior now have explicit regression coverage.

## Verification performed in the development environment

- Strict TypeScript check for consolidation/config and Firmware analyzer regression targets with isolated external dependency declarations.
