# Forensics++ v1.0.0-alpha.3

## 中文

这一版继续完善案件记录和时间线之间的衔接。

### 主要变化

- 时间线工具解析出的事件可以随“加入报告”登记到对应报告项。
- 报告预览新增解析出的时间事件数量。
- Markdown、JSON、Bundle JSON 和报告预览会保留时间、格式、来源、行号、原始值和上下文。
- 时间线登记只保存在当前页面内存中，不会额外扩大浏览器存储。
- 较大的报告和工作区状态会自动转入现有 IndexedDB，避免 localStorage 超限后静默丢失。
- 哈希清单按文件名进行精确核验，单独粘贴一个哈希时仍支持全局匹配。
- 支持导入 Bundle JSON；导入前会校验结构，并明确确认后才替换当前案件记录。
- 报告支持选择本地源文件进行 SHA-256 核验，并显示一致、不一致、未选择和未登记状态。

### 验证

- 83 个测试通过。
- TypeScript、版权头、生产构建和静态发布包校验通过。

## English

This release connects the Timeline Builder with the case report workflow without adding another storage layer.

### Highlights

- Parsed timeline events can be registered with a report item through the explicit “Add to Report” action.
- The report preview shows the number of parsed timeline events.
- Markdown, JSON, Bundle JSON, and the preview retain the normalized time, format, source, line number, raw value, and context.
- Timeline registration remains in page memory and does not increase browser storage.
- Larger report and workspace state automatically falls back to the existing IndexedDB store instead of silently failing at the localStorage quota.
- Standard checksum manifests now match by filename, while a standalone digest remains a global target.
- Bundle JSON can be imported after structural validation and an explicit replacement confirmation.
- Reports can verify selected local source files against the registered SHA-256 values after an explicit action.

### Verification

- 83 tests passed.
- TypeScript, copyright-header, production-build, and static-package verification passed.
